## A — Card format v2 (frozen contract)

`factory/human_in_the_loop.py` `escalate()` gains OPTIONAL kwargs (backward-compatible):
`meaning: str|None`, `needs: str|None`, `actions: list[dict]|None`, `fyi_only: bool = False`.
Each action dict: `{"action": "<imperative label>", "effect": "<what happens when approved>", "reply": "<exact approval grammar, e.g. 'approve action-1'>"}`.
Row gains a `card` block: `{"what_it_means", "what_it_needs", "approvable_actions": [...]}` or `{"what_it_means", "what_it_needs", "fyi_only": true}`.
A call supplying NONE of the new kwargs stamps `"card_gap": true` AND prefixes eli5 with `[unclear card] ` — gaps stay LOUD until every producer upgrades. Never raise on old-style calls.
Producers upgraded in this phase: `factory/manager.py` (the escalate_fn wrapper in main(): map known finding codes — budget_telemetry_missing, budget_near, runmanifest_red, runmanifest_unverified, release_drift, backlog_aging — to meaning/needs/actions; unknown codes get meaning=the detail string, needs="Ops review", fyi_only=true); `factory/estate_deadman.py` `raise_alarm` (meaning: the estate watchdog itself went quiet or a conductor heartbeat is stale; needs+action: inspect/restart, reply grammar); `departments/podcast/runtime/escalate_outbox.py` (candidates already carry what_it_means/what_it_needs/one_question — thread them into the card block; ops-repair classes are `fyi_only: true`).
CRITICAL COMPATIBILITY: some component validates podcast escalation packets ("packet does not match podcast escalation schema" — find it by grepping that string) — the new `card` field must be ADDITIVE: old rows still validate, new rows with `card` validate, and the validator must not strip or reject the block. Tests prove both directions.

## B — F3 sales runtime (frozen contracts)

Shared conventions: every node is a confined-launcher script mirroring podcast sensors — argparse `--state-dir --shadow` (+`--dept-dir` where noted), appends observations to `<state>/observations.jsonl`, ALWAYS `runrecord.emit_record` (status ok unless the node crashed; emission failure fatal; trigger dedupe_key `<date>-<node>`), exit 0 unless crashed. PII floor: emails/names exist ONLY under `state/sources/` (estate-fetched inputs) — everything a node WRITES uses `subject_id = hashlib.sha256((salt + email.strip().lower()).encode()).hexdigest()[:16]` with salt read from `<state>/sources/.id_salt` (missing salt file = crash, never a default salt).

Source file shapes (fixtures now, estate fetchers later), all under `<state>/sources/`:
- lane files `icaregrow.json`, `luma.json`, `website_forms.json`, `podcast_handoffs.json`, `pfs_warm.json`: `{"rows": [{"email", "name", "role", "icp_fit": bool?, "exit_intent": bool?, "ts"}]}`
- `calendar_events.json`: `{"events": [{"event_id", "attendee_email", "start", "minutes": int, "attended": bool, "decision_maker_present": bool}]}`
- `threads.json`: `{"threads": [{"email", "last_two_way_ts", "kind": "reply"|"live"}]}`

Nodes (each transition appended via `factory.events_ledger.append_event`; its same-UTC-day duplicate guard makes re-runs safe):
1. `intake_sensor.py`: parse the five lane files (missing file = counted, visible in the observation detail, never a crash); NEW arrivals (no received transition for subject in the ledger) append `arrival -> received` with `meta={"source": <lane>, "cohort": <ISO week, e.g. 2026-W32>}`; lane order for dedup priority: icaregrow, podcast_handoffs, pfs_warm, website_forms, luma — first lane wins, later same-day arrivals of the same subject are recorded in the observation as cross-lane duplicates (feeds gate B). Observation sensor `intake`, status ok / alarm (any unparseable file).
2. `qualify_scorer.py`: for ledger subjects with `received` and no `qualified` transition, find the source row by hash match; bar by lane: pfs_* -> seller (`role in {owner, decision_maker}` AND `exit_intent` true), else services (`role in {owner, decision_maker}` AND `icp_fit` true); qualified -> append `received -> qualified` + one line to `<state>/qualifications.jsonl` `{"subject_id", "bar": "services"|"seller", "evidence": {"role": ..., "icp_fit"|"exit_intent": ...}, "ts"}`; not qualified -> line to `<state>/parked_out.jsonl` with reason. Observation sensor `qualify`.
3. `booked_sensor.py`: calendar events whose attendee hash matches a subject with `qualified` (or later) and no `booked` transition -> append `qualified -> booked`... EXCEPTION: the ledger chain in the charter is received->qualified->conversation_live->booked; v1 proving slice SKIPS conversation_live for received-lane bookings (they book directly from qualification) — append `conversation_live -> booked` ONLY when a conversation exists, else append `qualified -> booked` and record `"fast_path": true` in the booking receipt; booking receipts to `<state>/bookings.jsonl` `{"subject_id", "event_id", "start", "fast_path": bool, "ts"}`. Observation sensor `booked`. (The floor compiler tolerates fast-path: its rate denominators are per-transition; fast-path bookings simply don't feed the conversation_live cascade row — honest, visible in counts.)
4. `held_sensor.py`: events with `attended` AND `decision_maker_present` AND `minutes >= 20` AND start in the past, for subjects with `booked` and no `held` -> append `booked -> held` + held receipt to `<state>/held.jsonl` `{"subject_id", "event_id", "minutes", "bar": <from qualifications.jsonl>, "source": <from the received transition meta>, "ts"}` — receipt REFUSED (observation alarm, no transition) when the bar or source cannot be resolved (attribution is part of DONE). Observation sensor `held`.
5. `sense_gates.py --state-dir --dept-dir`: the four context-is-king gates as observations (sensor `salesgate`): A staleness — subjects in `conversation_live` whose threads.json lacks a two-way within 7 days -> alarm listing count; B double-touch — subjects arriving via 2+ lanes within `per_contact_cadence_floor_days` (from the charter via charter_loader thresholds/budget) -> alarm; C context/voice coverage — drafts do not exist in v1: record `{"drafts": 0, "checked": 0}` status ok (vacuous truth made explicit); D floors attainment — read `<dept>/floors.yaml` (absent -> status unknown) and compare each stage's `flow_per_week` against this ISO week's ledger transition counts -> alarm with per-stage shortfalls. Escalation wiring comes at integration (coordinator adds card-v2 escalate calls after both patches merge).
